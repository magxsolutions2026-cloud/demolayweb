T-Shirt Fundraising Campaign Feature

This feature adds public T-shirt fundraising campaigns to the chapter feed and records every submitted order for admin review.

Public Flow

  1. An admin creates a campaign with campaign_type = tshirt.
  2. Active T-shirt campaigns automatically appear in the home page chapter feed.
  3. Brothers can open the campaign card, review details, choose a size, set quantity, and submit an order.
  4. The system validates the order window, size, quantity, and buyer information before saving the order.

Admin Flow

  1. Admins manage campaigns from the Chapter Funds workspace.
  2. Campaigns can now be marked as general or tshirt.
  3. T-shirt campaigns support a public slug, feed summary, description, cover image URL, unit price, and available sizes.
  4. The Chapter Funds workspace now includes a T-shirt orders tab with totals, size breakdown, search, filtering, and a buyer list.

Reporting Behavior

  • Campaign raised totals now include manual linked fund_sources and recorded campaign_orders.
  • Chapter-wide funds summary now includes T-shirt order revenue in total raised, monthly raised trend, and source distribution as merchandise.

Database Changes

Updated campaigns Table

Added columns:

  • slug
  • campaign_type
  • summary
  • description
  • cover_image_url
  • unit_price
  • size_options

New campaign_orders Table

Stores campaign reference, brother name, email, phone, shirt size, quantity, price snapshot, total amount, notes, and timestamp.

Key Routes

Public

  • POST /api/campaigns/[slug]/orders

Admin

  • GET /api/admin/funds/campaigns
  • POST /api/admin/funds/campaigns
  • GET /api/admin/funds/campaigns/[id]
  • PUT /api/admin/funds/campaigns/[id]
  • DELETE /api/admin/funds/campaigns/[id]
  • GET /api/admin/funds/orders
  • GET /api/admin/funds/summary

Setup

  1. Run db-migration-funds.sql.
  2. Run db-migration-tshirt-campaign-orders.sql.
  3. Optionally run db-seed-funds.sql for sample data.

Notes

  • T-shirt campaigns only accept orders while the campaign is active and within its start and end dates.
  • Campaigns with recorded orders cannot be deleted from the admin UI.
  • Validation passed with ./node_modules/.bin/eslint and ./node_modules/.bin/tsc --noEmit.
